## 3. P0：必须立即修复的问题

P0 项目影响结果含义或存在明确实现缺陷，应在继续调参前完成。

### 3.1 区分“周期相位投影”和“价格预测”

- [ ] 主图不再把去趋势周期线称为价格预测。
- [ ] 默认使用独立的标准化周期副图，纵轴范围建议为 `[-1, 1]`。
- [ ] 如果周期线继续叠加在价格图上，必须标注“视觉缩放，不代表目标价格”。
- [ ] 删除“投影区间累计上涨/下跌 X%”等容易被理解为价格收益的文案。
- [ ] 只有在实现“趋势 + 周期 + 预测区间”后，才允许显示未来目标价格。

**当前原因**

`scale_composite_to_price()` 用历史价格分位数缩放周期曲线，但缩放后的数值不是预测价格。当前未来线只外推正弦周期，没有外推被移除的价格趋势。

**解决方案**

提供两个明确模式：

1. `phase_only`：只输出周期方向、相位和转折窗口，不输出价格目标。
2. `price_forecast`：输出完整的对数价格预测：

```text
log_price(t) = trend(t) + cycle(t) + residual(t)
```

未来价格必须由未来趋势和未来周期共同构成：

```text
forecast_log_price(t+h)
    = forecast_trend(t+h)
    + forecast_cycle(t+h)
```

并转换回价格：

```text
forecast_price(t+h) = exp(forecast_log_price(t+h))
```

**完成检查**

- 相位模式中不出现 `$`、价格目标或伪收益百分比。
- 价格预测模式必须同时显示中位预测和预测区间。
- UI、日志和下载图表的命名完全一致。

### 3.2 修复 DFE 与 fallback 来源标记

- [ ] 每个周期单独保存来源：`dfe`、`fallback` 或 `manual`。
- [ ] 不允许两个默认周期被补入后仍显示整体来源为 `dfe`。
- [ ] 日志显示每个频率的功率、显著性、来源和通过/拒绝原因。
- [ ] 如果有效周期不足，允许只使用 0、1 或 2 个周期，不强行补满三个。

建议返回结构：

```python
@dataclass
class PeriodCandidate:
    period: float
    source: str
    power: float | None
    prominence: float | None
    stable: bool
    rejection_reason: str | None = None
```

示例日志：

```text
28.0d  source=dfe       prominence=0.31  accepted
127.0d source=fallback  disabled
227.0d source=fallback  disabled
```

**完成检查**

- 当前 VOO、QQQ 的 `[227, 127, 28]` 不得再显示为纯 DFE。
- 测试覆盖“找到 3 个、找到 1 个、完全找不到峰”三种情况。

### 3.3 周期长度必须满足可辨识条件

- [ ] 删除 `252 日拟合窗口 + 227 日周期` 的默认组合。
- [ ] 每个周期至少需要 2.5–3 个完整波段。
- [ ] 检测窗口、拟合窗口和最大周期使用同一约束。

约束建议：

```python
max_period = fit_window / min_cycles
min_cycles = 3.0
```

因此：

| 拟合窗口 | 建议最大周期 |
|---:|---:|
| 252 | 84 |
| 504 | 168 |
| 756 | 252 |

如果业务确实需要 227 日周期，拟合窗口至少应为约 681–756 日，而不是仅增加外层 lookback 后仍只拟合最近 252 日。

**完成检查**

- 所有进入回归的周期都通过 `fit_window / period >= min_cycles`。
- UI 在用户手动输入不可辨识周期时给出错误或降级提示。

### 3.4 改成联合谐波回归

- [ ] 不再分别拟合每个周期后相加。
- [ ] 一次性构建设计矩阵，并进行联合回归。
- [ ] 使用 Ridge 正则化控制周期之间的共线性。
- [ ] 在时间序列内层验证中选择正则化强度。

联合设计矩阵：

```text
X = [
    sin(2πt/P1), cos(2πt/P1),
    sin(2πt/P2), cos(2πt/P2),
    ...
]
```

加权 Ridge 解：

```text
β = argmin Σ w(t)·(residual(t) - X(t)β)² + λ||β||²
```

注意：

- `λ` 不能在完整历史或测试集上选择。
- 正则化通常不惩罚截距。
- 必须输出设计矩阵条件数；条件数过高时减少周期数量。

**完成检查**

- 合成拟合来自一次联合求解。
- 合成模型的训练误差不能因重复相加而异常放大。
- 对高度接近的两个周期有确定的剔除或正则化行为。

### 3.5 停止使用样本内 R² 作为未来置信度

- [ ] 保留 R²，但明确命名为 `in_sample_fit_r2`。
- [ ] 删除固定的 `R² >= 0.5 => 高置信度` 逻辑。
- [ ] 新置信度只能来自历史样本外校准。

新的输出应分开：

```text
样本内拟合质量: R²=0.59
历史样本外方向准确率: 51%
预测上涨概率: 54%
置信度: 低
```

**完成检查**

- R² 不再直接决定高、中、低置信度。
- 如果没有足够的样本外历史，置信度必须显示“未校准”。

### 3.6 使用调整后行情并明确价格口径

- [ ] 周期和收益分析默认使用复权 OHLC。
- [ ] 原始 Close 仅用于展示实际交易价格时保留。
- [ ] 对拆股、分红、缺失值和重复日期增加检查。
- [ ] 数据下载结果记录来源、下载时间和调整方式。

建议：

```python
yf.download(..., auto_adjust=True)
```

或者同时保留：

```text
raw_close
adjusted_close
adjustment_factor
```

**完成检查**

- 用已知拆股股票做测试，拆股日不能产生巨大虚假周期。
- VOO、QQQ 收益口径在报告中明确为价格收益或总回报近似。

## 4. P1：建立可信的验证框架

没有验证框架之前，不应继续根据单张图调周期参数。

### 4.1 Walk-forward 回测

- [ ] 每个预测点只允许读取当时及以前的数据。
- [ ] 每个预测点重新执行去趋势、选周期、选窗口、拟合和置信度计算。
- [ ] 超参数选择放在训练区间内部的时间序列验证中。
- [ ] 测试窗口与训练窗口严格分离。
- [ ] 5、20、65 日分别评估。
- [ ] 主报告使用不重叠未来窗口；重叠窗口结果仅作为补充。

推荐流程：

```text
外层训练数据
  └─ 内层 walk-forward：选择窗口、λ、峰值阈值
       └─ 用所选参数在外层训练数据重拟合
            └─ 预测从未参与调参的未来 H 日
```

如果使用重叠标签，应增加 purge/embargo，避免相邻样本共享大量未来区间。

### 4.2 必须加入的基准模型

- [ ] 始终看涨。
- [ ] 零收益/最后价格不变。
- [ ] 历史漂移随机游走。
- [ ] 20 日和 60 日动量。
- [ ] 简单均线趋势。
- [ ] 仅趋势、不含周期的模型。
- [ ] 当前周期模型。
- [ ] 改进后的趋势 + 周期模型。

周期模块的真实增量应通过以下比较得到：

```text
完整模型表现 - 仅趋势模型表现
```

如果完整模型不能稳定超过仅趋势模型，周期模块不应参与交易结论。

### 4.3 预测指标

方向模型至少报告：

- [ ] Accuracy。
- [ ] Balanced Accuracy。
- [ ] 上涨/下跌 Precision、Recall。
- [ ] MCC。
- [ ] 概率模型的 Brier Score。
- [ ] 概率校准曲线和 ECE。

数值预测至少报告：

- [ ] MAE。
- [ ] RMSE。
- [ ] 相对随机游走的 MASE。
- [ ] 预测收益与实际收益的 Pearson/Spearman 相关性。
- [ ] 预测区间覆盖率与平均宽度。

策略测试至少报告：

- [ ] 年化收益、波动率和 Sharpe。
- [ ] 最大回撤。
- [ ] 换手率和交易次数。
- [ ] 含成本与不含成本结果。
- [ ] 相对买入持有的超额收益。

### 4.4 统计不确定性

- [ ] 所有主要指标提供 95% 置信区间。
- [ ] 时间序列使用 block bootstrap，而不是逐日独立 bootstrap。
- [ ] 分牛市、熊市、高波动和低波动区间报告。
- [ ] 防止只展示最有利的标的或年份。

推荐最少样本要求：

- 5 日：至少 300 个不重叠样本。
- 20 日：至少 100 个不重叠样本。
- 65 日：至少 40 个不重叠样本，并明确小样本风险。
- 除 VOO、QQQ 外，加入不同资产与行业，但不能用扩展资产反复调参后再把它们称为测试集。

### 4.5 防止回测泄漏

- [ ] 不在完整数据上预先选择周期。
- [ ] 不用测试区间确定窗口长度。
- [ ] 不用未来高低点定义当时可见信号。
- [ ] 信号在收盘后生成时，只能从下一交易日开盘成交。
- [ ] 标准化参数只能用训练数据计算。
- [ ] 缓存必须按截止日期隔离，不能意外返回完整数据。

增加一个“未来数据不变性测试”：

```text
在 cutoff 后追加或修改任意未来数据，
cutoff 时刻的模型输出必须完全不变。
```

## 5. P2：周期模型重构方案

### 5.1 明确预测目标

推荐优先预测调整后对数价格或对数收益：

```text
y(t) = log(adjusted_close(t))
```

未来 H 日收益：

```text
r(t, H) = y(t+H) - y(t)
```

相比直接拟合价格，对数尺度可以减少不同价格阶段的异方差问题。

模型必须明确选择以下任务之一：

1. **方向分类**：预测 `P(r(t,H)>0)`。
2. **收益回归**：预测 `E[r(t,H)]` 和区间。
3. **转折检测**：预测未来转折窗口，不预测收益。

不要再用同一条周期线同时承担三种任务。

### 5.2 趋势模型

- [ ] 趋势与周期使用同一训练截止日期。
- [ ] 避免直接外推二次、三次多项式。
- [ ] 比较稳健线性趋势、局部线性趋势和阻尼趋势。
- [ ] 在样本外选择趋势模型。

推荐默认采用阻尼线性趋势：

```text
trend(t+h) = trend(t) + slope × damped_horizon(h)
```

随着预测期增加逐渐减弱趋势斜率，避免长期直线或二次曲线失控。

同时保留“零漂移趋势”作为强基准。

### 5.3 更稳健的周期提取

- [ ] 去趋势后再进行频谱分析。
- [ ] 对残差应用 Hann 窗，减少频谱泄漏。
- [ ] 比较 periodogram 与 Welch PSD。
- [ ] 峰值必须满足绝对和相对显著性要求。
- [ ] 峰值必须在多个相邻训练子窗口中稳定出现。
- [ ] 对接近周期和谐波关系给出明确处理。
- [ ] 不再用固定默认周期补足数量。

周期稳定性建议：

```text
在完整训练窗、去掉最近 20 日、去掉最早 20 日三个窗口上检测。
只有周期差异在 ±10% 内重复出现，才标记为 stable。
```

对稳定性不足的候选：

- 降低权重；
- 或直接不进入回归；
- 不应仅因为它是频谱最高峰就采用。

### 5.4 周期数量选择

- [ ] 允许零周期模型。
- [ ] 候选周期上限建议为 5，但最终数量由内层验证决定。
- [ ] 比较 0、1、2、3 个周期的样本外误差。
- [ ] 在表现接近时选择更少周期。

选择规则可以使用：

```text
one-standard-error rule
```

即在误差与最佳模型相差一个标准误以内时，选择最简单的模型，减少过拟合。

### 5.5 残差与不确定性

- [ ] 保存训练残差。
- [ ] 检查残差自相关、波动聚集和异常值。
- [ ] 使用移动区块残差 bootstrap 生成预测区间。
- [ ] 不只输出单条未来曲线。

建议输出：

```text
中位预测
50% 预测区间
80% 预测区间
```

如果 80% 区间同时覆盖明显上涨和明显下跌，模型应自动输出“无方向优势”。

### 5.6 锚定与连续性

- [ ] 未来预测必须从当前拟合状态自然延续。
- [ ] 检查历史最后一点与未来第一点的跳变。
- [ ] 不使用全历史价格分位数把周期幅度任意放大。

价格模式可以在最后观测点进行残差锚定：

```text
anchor_error = observed_log_price(t) - fitted_log_price(t)
```

锚定误差可在未来若干日内逐渐衰减，而不是永久平移整条曲线。

### 5.7 多窗口集成

单一窗口容易受起点影响。可在基础模型正确后增加：

- [ ] 252、504、756 日多窗口模型。
- [ ] 每个窗口独立选周期和拟合。
- [ ] 权重由过去样本外表现决定。
- [ ] 权重只能使用预测时点以前的历史。

最终预测：

```text
forecast = Σ calibrated_weight_i × forecast_i
```

如果各窗口方向冲突，应降低置信度，而不是强制给出单一结论。

## 6. P3：置信度与信号决策重构

### 6.1 样本外概率校准

- [ ] 保存历史预测值与真实结果。
- [ ] 用滚动历史进行 isotonic 或 logistic calibration。
- [ ] 校准器只使用当前预测点之前的历史。
- [ ] 样本不足时不输出精确概率。

示例：

```text
原始模型分数: +0.42
历史校准上涨概率: 56%
80%预测区间: -4.1% 至 +6.3%
结论: 方向优势不足，观望
```

### 6.2 设置 abstain/观望机制

模型不应每天都强制预测上涨或下跌。

- [ ] 概率接近 50% 时输出“无优势”。
- [ ] 预测区间过宽时输出“无优势”。
- [ ] 周期不稳定或数据质量异常时输出“模型不可用”。
- [ ] 趋势与周期冲突时降低仓位或观望。

初始阈值只用于启动验证，最终必须样本外确定。例如：

```text
P(up) >= 0.60：偏多
P(up) <= 0.40：偏空
其他：无优势
```

### 6.3 技术指标与周期模型解耦

- [ ] 分别回测 SuperTrend、TD、SQZ、CMF。
- [ ] 报告每个信号的独立增量。
- [ ] 不把 CMF 正值直接描述成“机构吸筹”。
- [ ] 不把趋势向上描述成“大势安全”。
- [ ] 不使用“可果断加仓”等未经验证的确定性措辞。

建议把规则转成结构化特征：

```text
trend_state
distance_to_supertrend_atr
td_setup_state
sqz_level
sqz_change
cmf_level
cycle_probability
cycle_stability
```

然后使用预先定义并可回测的评分规则，或在严格嵌套验证下训练简单模型。

### 6.4 交易执行规则

- [ ] 明确信号在何时生成。
- [ ] 收盘数据生成的信号从下一根开盘执行。
- [ ] 加入滑点、手续费和买卖价差。
- [ ] 仓位大小与波动率或最大风险挂钩。
- [ ] 止损规则使用当时可见的 ATR。
- [ ] 防止同一天先看到最高/最低价再假设以更优价格成交。

默认策略建议从简单版本开始：

```text
目标波动率仓位
+ 最大单标的仓位
+ 下一开盘成交
+ 双边成本
+ 无优势时空仓或保持基准仓位
```

### 7.3 文案分级

| 弱信号 | “历史校准后略偏多/偏空” |
| 强信号 | “历史同类信号表现较好，但仍存在损失风险” |

任何情况下都不使用“保证”“大势安全”“可果断加仓”等措辞。

## 8. P5：测试清单

### 8.1 单元测试

- [ ] 纯正弦合成数据可以恢复已知周期。
- [ ] 趋势 + 噪声数据不会虚构多个强周期。
- [ ] 无周期白噪声返回零周期或低置信度。
- [ ] 两个接近周期不会因独立拟合重复放大。
- [ ] 手动周期超过可辨识上限会被拒绝。
- [ ] 部分 fallback 来源正确。
- [ ] 联合 Ridge 在奇异矩阵情况下稳定。
- [ ] 空数据、短数据、常数价格和零成交量正确处理。
- [ ] 拆股数据经过调整后不产生断点。
- [ ] 预测日期使用交易所日历而不是普通工作日日历。

### 8.2 时序安全测试

- [ ] 修改 cutoff 之后的数据不改变 cutoff 时刻预测。
- [ ] 内层调参从未读取外层测试数据。
- [ ] 滚动标准化只使用过去数据。
- [ ] 信号成交价不早于信号生成时间。

### 8.3 回归测试

- [ ] 固定小数据集与随机种子。
- [ ] 保存核心模型的预期输出摘要。
- [ ] 每次代码修改自动比较 OOS 指标。
- [ ] 不允许只因样本内 R² 上升就通过模型升级。

### 8.4 性能测试

- [ ] 单标的一次分析目标小于 3 秒。
- [ ] VOO、QQQ 全历史 walk-forward 可断点续跑。
- [ ] 缓存按标的、数据截止日、参数和代码版本区分。

## 11. 上线验收门槛

### 11.1 工程门槛

- [ ] 所有周期都有正确来源。
- [ ] 所有周期满足最少完整波段数。
- [ ] 无前视偏差测试通过。
- [ ] 合成数据和异常数据测试通过。
- [ ] 同一数据、参数和版本可以完全复现结果。

### 11.2 预测门槛

至少在 VOO、QQQ 和预先冻结的额外测试资产上满足：

- [ ] 相对随机游走的 OOS MAE 有稳定改善。
- [ ] 方向 Balanced Accuracy 超过简单基准，而不只是超过 50%。
- [ ] 预测收益与实际收益相关性方向一致，并有合理置信区间。
- [ ] 高置信度组明显优于低置信度组。
- [ ] 80% 预测区间覆盖率接近目标，而不是过窄。
- [ ] 不同市场阶段没有单一阶段贡献全部收益。

建议升级门槛：

```text
OOS MAE 相对最佳朴素基准改善 >= 3%
Balanced Accuracy 相对最佳方向基准改善 >= 2 个百分点
高置信度样本数 >= 50，且命中率至少高于对应基准 5 个百分点
```

这些门槛如果未通过，应保留为研究/可视化工具，不启用交易建议。

### 11.3 策略门槛

- [ ] 含成本后仍优于对应基准。
- [ ] 收益不依赖少数几笔交易。
- [ ] 最大回撤和仓位风险在预设范围。
- [ ] 参数在邻近取值下表现平滑，而不是只有一个尖锐最优点。
- [ ] 完全独立的最终测试区间只评估一次。

## 12. 推荐的第一版落地范围

第一版不要同时引入复杂机器学习。建议只实现以下最小但可信的组合：

1. 调整后对数价格。
2. 504 或 756 日训练窗口。
3. 最少 3 个完整周期。
4. 无硬编码周期补齐。
5. 稳定频谱峰筛选。
6. 联合 Ridge 谐波回归。
7. 阻尼线性趋势。
8. 残差 block bootstrap 预测区间。
9. 嵌套 walk-forward。
10. 样本外概率校准与观望机制。

只有这个版本在冻结测试集上超过基准后，才考虑：

- 多窗口集成；
- 状态空间模型；
- 机器学习信号组合；
- 更复杂的仓位优化。

这样可以清楚判断“周期本身有没有增量”，避免复杂度增加后仍无法解释模型为什么有效。
